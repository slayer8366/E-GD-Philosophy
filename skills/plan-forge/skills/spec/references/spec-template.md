# Spec Template

Use these headings in this order. Omit a heading only if it is truly empty; write "None" rather than dropping it.

## Goal
One sentence. What changes for the user when this ships.

## Scope
What is in. Bullet list, each item one line.

## Out of scope
What is deliberately not included, and why if not obvious.

## Decisions
Choices already made, each with a one-line reason. These are the parts an implementer must not revisit.

## Requirements
Numbered. Each one testable. Format: `R1. <behaviour>. Check: <how it is verified>.`

## Constraints
Do-not-touch areas, performance limits, compatibility needs.

## Acceptance
The short list of checks that mean done. Prefer observable outcomes over implementation details.

## Unverified
Claims in this spec that rest on assumption rather than a read of the code or data.

## Open questions
Decisions still owed by the author. "None" if empty.
