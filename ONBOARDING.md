# Onboarding

How someone starts working with Evidence Gated Development, and how the agents learn what that person wants and how they want it. Written 2026-10-17 (RECORD.md 2026-10-17-19), at the operator's request: "Let's try to rebuild it and give this philosophy an onboarding process."

## 1. Clio says hello

Clio, E-GD's curator, introduces itself to the new operator:
- the name;
- that Clio looks after the method and its tools;
- that they are welcome to use them;
- that feedback is wanted, and goes to E-GD's operator for approval.

## 2. How do you like to work?

The first question, in these words or close to them:

> Do you have specific styles or instructions in mind for how we work together: how you like to be asked things, how you like results reported, what you decide yourself? Or shall I learn them as we go?

Three answers, each fine:
- **They have some in mind.** Write each into their operator profile in their own words, and read the profile back before it is used.
- **Learn as we go.** Start the profile from the template, its sections empty.
- **Start from what's recorded.** If they have worked with agents before, draft the profile from their recorded words, each line cited, and show it to them first.

## 3. The operator profile

Copy OPERATOR_PROFILE.template.md into the project, for example as docs/process/operator-profile.md, and fill it from step 2. Each project keeps its own (the operator, 2026-10-17: "In each project"). Every role reads it at the start of each session.

## 4. Learning as you go

When the operator states a preference, or corrects how they were asked or told something:
1. Propose a line for the profile, quoting their words, and ask whether to add it.
2. Add it only if they say yes, with the date and where it was said.
3. Never add a one-time override, a re-ask that changed nothing, or an explanation of something misread.

## 5. Setting up the method

Then follow OVERVIEW.md, "Getting started":
- install BOOTSTRAP.md where the agents will see it;
- set up the record (RECORDING.md), its checkers (ADOPTING.md) and the prompts folder;
- name each role and give it a profile (PROTOCOL rule 22);
- run one small task through the whole loop.

## 6. Feedback

Feedback on the method or its tools is welcome at any time: an issue at github.com/slayer8366/E-GD-Philosophy/issues (the "Feedback for Clio" form), or tell E-GD's curator. Clio brings it to E-GD's operator, who decides what changes in E-GD. What changes in your own project is yours to decide.
