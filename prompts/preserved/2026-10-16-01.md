## Lessons

**1. A check only counts if it could have failed.** *Philosophy, new principle; n ≥ 15*
- **Forager:** the same failure turned up in five forms:
  - a migration test that passed with the migration removed, because the default gave the same answer;
  - a revert run that read the previous run's results, because the reverted build never compiled;
  - a log parser that silently dropped the 55 cases that could have disproved it;
  - a check built for a code path that nothing calls;
  - a record checker that checks its own folder whatever you point it at, so it reported PASS on the wrong repository (entry -544).
- **Tools that check the tests failed the same way** (n = 6): a compile guard reading the wrong output stream, so it could never fire, and a hook suite blind to its own config, among others.
- **"A red that proves nothing":** the fail-first rule was followed exactly, and the red result was still worthless.
- **Science link:** this is Popper's falsifiability made practical by Deborah Mayo's "severity": a test supports a claim only if it would probably have failed were the claim false.
- **Proposal:** one principle tying together E-GD's existing fail-first and checks-decay principles and protocol rule 5. Before citing any check, confirm four things:
  1. The path it tests is actually called by something.
  2. Its sample includes the case that could fail it.
  3. The red came from the same unchanged test that later goes green.
  4. The tool's output describes the state it claims to describe.

**2. A claim carries when it was true.** *Philosophy: amend "Sourced Claims" and promote protocol rules 1–2 into it; n > 10*
- **Forager:** the planner was given read access so it would stop asserting from memory. It kept doing it anyway: at least 24 record entries describe planner slips. One example: telling you tracks could be deleted by swiping, when the app has no way to delete a track.
- Read access was supposed to be measured. It never was.
- Figures were quoted outside the sample they came from (n = 4).
- "Doesn't exist" claims turned out false (n = 4). One said a flake had never been recorded when six records of it already existed.
- 37 record timestamps were guessed rather than read from the clock.
- **Proposal:**
  - Every claim names its source and the commit or time it was read.
  - A claim expires once that state can have changed.
  - A "doesn't exist" claim names the search behind it and how far that search reached.

**3. Durability is about where work lives.** *Philosophy, new principle; n = 8*
- E-GD lost its first record store because it was never pushed. `DURABILITY.md` wrote down the rule, but it never became a principle.
- Forager lost a Phase 1 audit outright.
- It nearly lost work again when unpushed commits were tidied.
- Four findings existed only in chat transcripts.
- **Proposal:**
  - Work isn't done until it's pushed.
  - Unpushed history is never rewritten to make it neater.
  - Reports gain an "observed, not asked" slot so findings made in passing get written down.

**4. Permission is explicit, local, and separate from deciding.** *Philosophy: refine "Operator Authority"; n = 10*
- **Forager:**
  - A "go" was read from another session's window (n = 3).
  - An answer to a design question was taken as a go to build (n = 2, including the Oct 14 stage 2 undo).
  - Paraphrases picked up your authority (n = 5): answers became "the owner's rule 6". One misread rule cost an hour and 3,369 passing tests on the wrong behaviour.
- **What fixed it:** restating the change as a step path, quoting you verbatim, and asking "start a coder now?" as its own question.
- **Correction to E-GD:** E-GD makes you review every prompt before it goes out. What actually worked in Forager is you confirming each decision restated in your own terms. Agreeing to the order of work never covered how a rule would be read.

**5. Fix the analysis before seeing the data, and have someone else redo it.** *Mostly from forager-forecast; refines "Intent-Driven Engineering" plus a new "Independent Replication" principle*
- **Fix choices first:** thresholds, samples, seeds and tolerances are committed before any data is read, and reviewers check the commit order (4 orderings checked).
  - It held twice when the result pulled the other way.
  - It caught one bad tolerance before any value was read.
- **Independent review:** 21 reviews, of which 14 led to a fix (the reader's classification). In one, the independent reviewer found two things the builder's own check missed. E-GD's own finding "one investigation is one sample" predicted this.
- **Protocol rule 9:** its withheld-hash method was never used in Forager. Public commit order did the same job, so rule 9 should point to that.

**6. Gates cost something, and the cost decides whether they survive.** *Refine "Automated Boundary Enforcement" and E-GD's self-application section*
- **What happened to the kit:**
  - It took six review rounds to build.
  - Per-dispatch approval lasted four days ("Can't have me hitting buttons").
  - The whole kit was switched off and deleted on Sep 27 because of usage limits.
  - Its "temp fix" label was never followed by an undo.
- **What decayed afterwards:**
  - Predictions disappeared from intents: 99 of 100 had one before Sep 30, 0 of 143 after.
  - The record built up 1,646 format errors and 307 broken links without anyone noticing.
  - The pre-main branch was bypassed for about two weeks.
- **What survived without enforcement:** dispatches as files, verbatim quotes, revert checks, and the pre-build disclosure sections (roughly 90–100 of 258 audit documents).
- **Proposal:**
  - Price each gate's running cost.
  - Prefer checks at commit or in CI over checks on every action.
  - A guard that runs in only some checkouts or routes doesn't protect the rest.
  - When a gate is removed, record what stops being enforced. Your Sep 27 note does exactly this.

**7. Roles split by what a decision depends on.** *Evidence for protocol rule 7; stays in protocol*

- The planner also reads the repo and writes records. Both are departures from E-GD's role split.

**8. Parallel work collides on more than code.** *Refine "Concurrency Awareness"; n ≥ 6*

- **Proposal:**

  - Add a continuation entry type.
  - Admission rule: clarify first, then record once.

**10. Honesty beats ease in what people see.** *Correct "Presentation Is Not Acquisition"*
- E-GD says display paths "may transform data freely." The field-instrument rules and "Don't make me think" say a display can change a fact's form but never remove or soften it. "Freely" is too strong.
- The evidence here is moderate; the skill itself says some of its rules are inferred.
